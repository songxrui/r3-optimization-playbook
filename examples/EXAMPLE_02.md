# EXAMPLE_02: 反面案例 — 模式滥用：对不需要的 skill 强行套所有模式

## 反例
```
skill: weread-skills (工具类，调 CLI 取数据)
所谓的 "R3 优化":
  套了模式 2 (视觉锻造) → 加了 ASCII 图
  套了模式 4 (联动图锻造) → 画了复杂的架构图
  套了模式 6 (字数膨胀) → 从 1KB 膨胀到 8KB
```

## 为什么是反例
1. **模式不匹配**: weread-skills 是工具/CLI skill，不需要视觉和联动图
2. **为套而套**: 不是因为需要，而是因为"playbook 有 7 个模式所以全用"
3. **反而劣化**: 加了无关内容 → 触发精度降低 → 上下文污染
4. **反模式 #2**: "全量模式套用"——不是所有 skill 都需要所有模式

## 正确做法
- 先判断 skill 类型: 工具/诊断/创作/编排 → 选择对应模式
- 工具类: 模式 1 (description) + 模式 3 (工作流) 就够了
- 创作类: + 模式 2 (视觉) + 模式 4 (联动)
- 绝不允许"因为 playbook 有所以就全用"

## skill-overseer 检测方式
- 检查优化后 skill 大小是否暴涨(不正常)
- 检查新增内容是否与 skill 类型匹配
- 检测是否有"装饰性"内容（无实际调用价值）
